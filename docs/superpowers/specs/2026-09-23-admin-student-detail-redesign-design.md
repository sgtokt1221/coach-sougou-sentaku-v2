# 生徒詳細の作り直し（要点の帯＋時系列）とスキルチェックの廃止

作成日: 2026-09-23
対象: `/admin/students/[id]`（管理者・講師の生徒詳細）、ランク（スキルバッジ）の算出、スキルチェック（小論文・面接）
モックアップ: `.superpowers/brainstorm/31700-1790170545/content/layout-a-v3.html`（ローカル。gitignore 済み）

## 1. 目的

生徒詳細は「面談前に状況をつかむ」「担当生徒を見回る」「提出物を読む・コメントする」「設定・事務」の
**全部の場面**で開かれる（2026-09-23 の聞き取り）。今の画面はどの場面にも最適化されていない。

| 今の問題                             | 実例（エミュレータで確認）                                                                                                       |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| 開いてすぐ状況が分からない           | 上部は最終活動と最終ログインだけ。期限・未提出・重要な弱点・次の面談は別々のタブの中                                             |
| 概要タブが長く、学習と事務が混ざる   | 概要タブは縦 約5,000px。スキル・プロフィール・機能スイッチ・探究授業・活動量・弱点・自己分析（木の絵＋7枚）・削除が1本に積まれる |
| 提出物の履歴が種類ごとに分かれている | 成績タブに 添削・面接・要約・ちょこ・論理・テーマ別 の折りたたみが8つ。中身を見るには1つずつ開く                                 |
| 「生徒の削除」が全タブの末尾に出る   | 危険な操作が学習の情報の下に常にある                                                                                             |
| スキルチェックが使われていない       | 受験はほぼ無く、ランクの 40% を占めるのに実態を表さない                                                                          |

## 2. 決定事項

| 論点           | 決定                                                                             |
| -------------- | -------------------------------------------------------------------------------- |
| 画面の形       | **A 案: 上に要点の帯、下に時系列**（B: 左カルテ固定、C: 今のタブ維持 は不採用）  |
| スキルチェック | **小論文・面接とも廃止**。生徒・管理者の画面から完全に消す。**データは消さない** |
| ランクの算出   | **普段の提出の平均だけ**で決める（今は スキルチェック 40% ＋ 練習の平均 60%）    |
| 平均の範囲     | **直近10件**（全期間だと初期の低い点が伸びを隠す）                               |

## 3. ランク（スキルバッジ）

- 使う記録は、**今の「練習の平均」に入っている記録と同じ**（`aggregate.ts` の練習側の集計）。変えるのは
  スキルチェックを外すことと、平均の範囲だけ。
  - 小論文: 添削した答案（`essays`、採点済み）の合計点。ちょこ添削は今と同じく重み 0.5（`CHOCO_WEIGHT`）。
  - 面接: 模擬面接（`interviews`、採点済み）の合計点。
- 満点の違う記録（口頭試問型 60点、面接の満点違い）は `normalizedEssayTotal()` / `interviewTotalMax()` で揃えてから平均する。
- 範囲は**新しい順に重みの合計が10に達するまで**（本添削は1件、ちょこ添削は0.5件として数える。
  例: 本添削8件＋ちょこ4件で10）。平均は重み付き平均。
- 0件は「未提出」（ランクを出さない）。
- ランクの境界は今の `scoreToSkillRank()`（`src/lib/history-rank.ts`）をそのまま使う。
- 算出は `src/lib/skill-check/aggregate.ts` の合成（blend）を「練習の平均のみ」にする。キャッシュ
  （`refreshEssayAggregateCache` 等）の置き場所と更新契機は変えない。表示に出ていた内訳
  「SC ○ × 40% ＋ 練習平均 ○ × 60%」は「直近○件の平均」に置き換える。

## 4. スキルチェックの廃止

データ（`users/*/skillChecks`・`users/*/interviewSkillChecks`）は消さない。消すのは画面と入口。

| 場所                                                                                        | 対応                                                                                                                                            |
| ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 生徒のサイドバー・モバイルメニューの入口                                                    | 消す                                                                                                                                            |
| `/student/skill-check`・`/student/interview-skill-check` 配下の画面                         | 開かれたら `/student/dashboard` へ移す                                                                                                          |
| ダッシュボードの「ベンチマーク再測定のおすすめ」                                            | 消す                                                                                                                                            |
| ランクの内訳表示（SkillRankCard 等）                                                        | 「直近○件の平均」に置き換え                                                                                                                     |
| 管理者の生徒詳細: スキルチェック履歴・スキルチェック系統の設定                              | 消す                                                                                                                                            |
| 面談画面（SessionStudentDossier）のスキル欄のスキルチェック部分                             | 消す                                                                                                                                            |
| 受験・採点の API（`/api/skill-check/*`・`/api/interview-skill-check/*` の開始・提出・終了） | 410 を返す（古い画面が開いたままでも新しい受験を作らない）                                                                                      |
| 管理者の読み取り API（`/api/admin/students/[id]/skill-check` 等）                           | 画面から呼ばなくなるので消す                                                                                                                    |
| スキルチェック系統（`academicCategory`）                                                    | 生徒一覧（`/api/admin/students`）が返しているので、一覧で表示・絞り込みに使っていないかを実装時に確かめる。スキルチェック以外で使っていれば残す |

## 5. 生徒詳細の画面

### 5.1 ヘッダー（1行）

名前・学年・第一志望（大学・学部）・担当講師・最終活動。右に3つのボタン:

- 「メッセージ」: メッセージのページ（`/admin/messages/[生徒ID]`）へ移る。今の「メッセージ」タブの中身は
  担当講師の割り当てだけで、やりとりはここには無い
- 「宿題を出す」: 既存の `CreateHomeworkDialog` を開く
- 「設定」: 5.6 のパネルを開く
  活動状態のバッジ（アクティブ／やや停滞／非アクティブ）は今の判定をそのまま使う。

### 5.2 要点の帯（4枚・ベタ塗り）

面で区切るときはベタ塗り（design-preferences）。白地に色帯のカードは使わない。数字は 28px を超えない。

| 帯         | 中身                                                                                                                                                                        | 空のとき                             |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| ランク     | 小論文・面接のランクと平均点（直近10件）、推移の小さな線。「詳しく見る」で成績・弱点へ                                                                                      | 「未提出」                           |
| 要対応     | 件数と中身: (1) 期限が7日以内（当日・超過を含む）で `status` が draft の出願書類（完成は `isDocumentComplete` ＝ draft 以外） (2) 未提出で、`dueDate` が過ぎた、または2日以内の宿題 (3) 講師がまだ開いていない提出物 | 緑で「対応が必要なものはありません」 |
| 重要な弱点 | 段階が「重要」「注意」の弱点を最大3件、「直近5回中4回」の形で。判定は `getWeaknessReminderLevel()`（直近の記録 `recentHits`）。「詳しく見る」で成績・弱点へ                 | 「重要な弱点はありません」           |
| 次の面談   | 予定の日時。前回の面談の `debrief.nextAgendaSeed`（無ければ `notes` の先頭）を1行                                                                                           | 「予定なし」                         |

- (3) の「まだ開いていない」は今の未確認の仕組み（`/api/admin/unviewed-submissions`、`byStudentKind`）を使う。
- 状態は色だけに頼らない（件数と文言を必ず出す）。

### 5.3 切り替え（帯の下）

`時系列`（既定）/ `成績・弱点` / `書類・実績` / `自己分析` / `レポート`

- URL の `?view=` に残す。今の `?tab=` で来たリンク（通知など）は読み替える:
  `overview→timeline`、`performance→performance`、`activity→documents`、`reports→reports`、
  `homework→timeline`（宿題で絞る）、`messages→` 設定のパネルを開く（中身が担当講師の割り当てだったため）。
- 下へ送っても切り替えは上に固定する。帯は流す。
- スマホは今と同じくドロップダウン。

### 5.4 時系列

- 種類: 小論文・面接・ちょこ添削・要約ドリル・論理ドリル・テーマ別ドリル・出願書類・面談・宿題・AI対話。
  種類で絞る（チップ、複数選択ではなく1つ）。
- 新しい順に20件ずつ。「もっと見る」で続きを読む。
- 行: 日付・種類・題（お題・書類名・面談の種別など）・点（あるものだけ、満点つき）。まだ開いていない行に赤い点。
- 行を開くと、今と同じ詳細（答案詳細のダイアログ・書類詳細・面談ページ等）を出す。
- 宿題の行は状態（未提出／提出済み／期限切れ）と期限を出す。今の「宿題」タブの一覧はこれで置き換える。
- 上に直近30日の活動量を小さな棒で出す（今の「活動状況」グラフを縮めたもの）。

### 5.5 各切り替えの中身（今の部品の置き場所）

| 切り替え   | 中身                                                                                   |
| ---------- | -------------------------------------------------------------------------------------- |
| 成績・弱点 | 項目別の平均（小論文・面接）、スコア推移、弱点一覧、重点弱点（カテゴリ別）、講座の進み |
| 書類・実績 | 出願書類の表、活動実績、受験結果                                                       |
| 自己分析   | 自己分析の進み（木は小さく）、7項目は折りたたみ既定                                    |
| レポート   | 成長レポート                                                                           |

### 5.6 設定（右から開くパネル）

プロフィール編集・パスワード再設定・機能スイッチ・プラン・担当講師の割り当て・探究授業の登録・生徒の削除。
**講師（`isTeacherViewer`）に見せる項目は今の表示条件をそのまま使う**（プラン・探究授業の登録・担当講師の
割り当ては今も講師には出していない）。削除は今と同じ確認ダイアログを通す。

## 6. データと API

### 6.1 時系列の API（新規）

`GET /api/admin/students/[id]/timeline?kind=<種類|all>&before=<ISO>&limit=20`

- 認可は今の生徒詳細の API と同じ（`requireRole` ＋ managedBy／組織のスコープ）。
- 種類ごとに `before` より古いものを最大 `limit` 件ずつ読み、日時で合わせて新しい順に `limit` 件返す。
  返す `nextBefore` で続きを読む。
- 行の形: `{ kind, id, at, title, score?: { value, max }, href?: string, unviewed: boolean }`。
- 1ページで読むのは 種類数 × `limit`（最大 10×20＝200件）。生徒1人分なので許容する。
- **一部の種類だけ読めなかったときは、読めた分を返し、`failedKinds` に種類を入れる。** 画面は
  「面談の記録を読み込めませんでした」のように出す（黙って欠けると、その種類が無いように見える）。
- 日時の型はコレクションごとに違う（CLAUDE.md 6.5）。Timestamp（`essays.submittedAt` 等）と ISO 文字列
  （`sessions.scheduledAt`・`documents`・`chokoReviews` 等）を、読む側で両対応して揃える。
- 範囲条件は各コレクションの型に合わせた値で書く（Date と文字列を取り違えると一致0件の沈黙失敗）。
- 新しい複合インデックスが要る場合は `firestore.indexes.json` に足し、デプロイ前に
  `firebase deploy --only firestore:indexes` を実行する（確認を取る）。

### 6.2 要点の帯の API

今の生徒詳細の API（`/api/admin/students/[id]`）の応答に `summary` を足す:
`{ rank: { essay, interview }, actionItems: [...], topWeaknesses: [...], nextSession, lastDebrief }`。
帯のために別の往復を増やさない。弱点は `loadWeaknessRecords()`（weakness-store）で読む。

## 7. やらないこと

- スキルチェックのデータ削除
- 時系列の行の中での編集（コメントは今の詳細のダイアログで行う）
- 生徒側の画面の作り直し（スキルチェックの入口を消す以外）
- 面談画面（レッスンシート）の作り直し（スキルチェック部分を消す以外）

## 8. 検証

- ランク: 直近10件・ちょこ0.5・満点違いの正規化・0件の「未提出」を、AI も DB も使わない検査
  （`scripts/verify-*.ts`、validate:data に連結）で固定する。
- 時系列 API: エミュレータで各種類を1件以上入れ、日時の型が混ざっても新しい順に正しく並ぶこと、
  `before` で重複・欠落なく続きが読めることを確かめる。
- 画面: エミュレータで管理者・講師（`isTeacherViewer`）の両方で開き、帯の4枚・切り替え・設定のパネル・
  古い `?tab=` のリンクの読み替え・スマホ幅（375px）を確認する。コンソールエラーが無いこと。
- スキルチェック: 生徒のメニューに出ないこと、古い URL がダッシュボードへ移ること、提出 API が 410 を返すこと。

## 9. 進め方

1. ランクの算出を変え、スキルチェックを画面から消す（生徒・管理者・面談画面）
2. 時系列 API と帯の `summary` を作る
3. 生徒詳細を組み替える（ヘッダー・帯・切り替え・設定のパネル）
4. 古い部品のうち使わなくなったもの（スキルチェック関連のコンポーネント・API）を消す

1 は単独で出せる（ランクの変化は生徒にも見える）。2〜3 はまとめて出す。
