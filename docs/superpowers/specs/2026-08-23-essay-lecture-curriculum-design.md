# 小論文講座リニューアル：カリキュラム設計

作成日: 2026-08-23
対象: `/student/essay/lectures`（既存の小論文講座を作り替える）

## 1. 目的

小論文の書き方を、アニメーション講義 →（文のドリル）→ 型に沿った課題 → AI添削 の流れで
学べるようにする。既存の8講（テキスト解説＋関連問題）を骨格として残し、次の3点を足す。

1. 解説をステップアニメーションにする
2. 「型」を縦串として、講義・課題・添削の観点を同じ語彙で貫く
3. 型では直らない**文の精度**（てにをは・主述の一致・一文の長さ等）を反復訓練する

## 2. 前提（決定済み）

| 論点             | 決定                                                                        |
| ---------------- | --------------------------------------------------------------------------- |
| 既存講座との関係 | 作り直さず、既存コーナーに足す形で拡張する                                  |
| 型の粒度         | 設問タイプ別の答案型（テーマ型・課題文型・資料型・解決策提示型）            |
| アニメ形式       | コードで作るステップアニメ（framer-motion）。動画は使わない                 |
| 課題の設計       | 型のブロック単位で段階的に（前半は1ブロック50〜150字、Phase 4からフル答案） |
| 文のドリル       | 講義の中に埋め込む（アニメ → ドリル → 課題で1講が完結）                     |

## 3. 全体構造：3つの層

小論文の力を3層に分け、1講の中で3層すべてに触れる。

| 層         | 何を鍛えるか                         | 講義での扱い                   | AI採点軸との対応             |
| ---------- | ------------------------------------ | ------------------------------ | ---------------------------- |
| 設計（型） | どの順で何を書くか                   | アニメ講義の主題               | 構成(12) / 論証(12)          |
| 文の精度   | 1文単位の正確さ・読みやすさ          | 埋め込みドリル                 | 表現力(11)                   |
| 中身の質   | 事実と意見の区別、具体性、自分の視点 | Phase 2 の講義＋課題の添削観点 | 独自性(5) / 議論の成熟度(10) |

3層に分ける理由は、直し方が違うから。型は理解すれば使える。中身は材料と考え方が要る。
文の精度だけは反復しないと直らない（講義で「気をつけよう」と言っても直らない）。

### 既存機能との棲み分け

| 既存                          | 役割                                                   | 本カリキュラムとの関係                                                             |
| ----------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| 論理ドリル                    | 因果の誤り・循環論法・過度な一般化・論点すり替え・飛躍 | 論理の**誤り検出**は既存に任せ、講義では扱わない。Phase 2 から誘導する             |
| 要約ドリル                    | 要約力                                                 | 13講「課題文の読み方」から誘導する                                                 |
| ちょこ添削                    | 完成答案の1段落だけ書く                                | 型のブロック課題と役割が近い。**講座の課題は型のブロック名で採点する**点で区別する |
| ネタインプット / 学部別テーマ | 材料の仕入れ                                           | Phase 2「中身の質」から誘導する                                                    |
| 本添削（essay review）        | 完成答案の総合採点                                     | Phase 4 以降の課題はここを通す（既存どおり `sourceType: "lecture"`）               |

## 4. 型のカタログ

### 4.1 基本型（6ブロック）

全講義・全課題・添削フィードバックで**この6つの名前だけ**を使う。呼び名を統一しないと、
「構成が弱い」という指摘が生徒の中で講義とつながらない。

| #   | ブロック     | 役割                               | 書き出しの例                     |
| --- | ------------ | ---------------------------------- | -------------------------------- |
| ①   | 問い         | 何を論じるかを自分の言葉で確定する | 「本問が問うているのは〜である」 |
| ②   | 立場         | 問いに直接答える。一つに決める     | 「私は〜と考える」               |
| ③   | 理由         | なぜその立場を取るのか             | 「なぜなら〜だからである」       |
| ④   | 根拠・具体例 | 理由を支える事実・経験・データ     | 「実際、〜」                     |
| ⑤   | 譲歩と反論   | 想定反論を受け止めてから切り返す   | 「確かに〜。しかし〜」           |
| ⑥   | 結論         | 立場を言い直して閉じる             | 「したがって〜」                 |

### 4.2 設問タイプ別の変形

基本型のどのブロックが置き換わるかで説明する。新しい型を4つ覚えるのではなく、
**1つの型の変形**として教える。

| 型                                                 | 変形点                                                                                    | 字数配分の目安（800字）                    |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------ |
| テーマ型<br>「〜について論じなさい」               | ①が重い。テーマから**自分で論点を立てる**工程が要る                                       | ①120 ②60 ③160 ④240 ⑤140 ⑥80                |
| 課題文型<br>「筆者の主張を踏まえ〜」               | ①を「筆者の主張の要約」に置換。②で賛否を明示。④は課題文の記述＋自分の材料                 | ①160 ②60 ③140 ④220 ⑤140 ⑥80                |
| 資料・データ型<br>「グラフから読み取れることを〜」 | ①を「読み取り（事実）」に置換し、②の前に「解釈」を挟む**7ブロック**。相関を因果と書かない | 読取160 解釈120 ②60 ③120 ④180 ⑤100 ⑥60     |
| 解決策提示型<br>「〜の課題と解決策を述べよ」       | ③理由を「原因」に、④を「解決策＋実現可能性」に置換。⑤で副作用・コストに触れる             | ①120 ②60 現状80 原因160 解決策220 ⑤100 ⑥60 |

各型には「使ってはいけない場面」も併記する（例：課題文型で要約が③④を圧迫する、
テーマ型で論点を立てずに一般論を並べる）。型の暴走が減点になることを最初に見せる。

## 5. 文のドリル（埋め込み型）

1回3分・5問。講義アニメの直後、課題の前に置く。

| ドリル           | 内容                                     | P1（選択式・AI不要） | P2（書き直し式）         |
| ---------------- | ---------------------------------------- | -------------------- | ------------------------ |
| てにをは         | 助詞の選択、「は」と「が」、助詞の重複   | 空欄に入る助詞を4択  | —                        |
| 主述の一致       | ねじれ文（「私の夢は医師になりたい」）   | 正しく直した文を4択  | 自分で書き直す（AI判定） |
| 一文を切る       | 90字超の一文を割る                       | 切り方を4択          | 自分で割る（AI判定）     |
| 係り受け・指示語 | 修飾語の位置、「その」が指す先           | 正しい語順を4択      | 自分で直す（AI判定）     |
| 文末・語彙       | 常体で統一、「〜と思う」の乱用、話し言葉 | 書き言葉を4択        | —                        |
| 冗長             | 「〜することができる」→「〜できる」      | 短く直した文を4択    | —                        |

**P1 は全問4択にする。** 書き直し式は AI 判定が要り、反復するほど課金が増える。
ここは「反復しないと直らない」種類の訓練なので、まずコスト0で何度でも回せる形を作り、
書き直し式は P2 で本人の答案（`languageCorrections`）を素材にして足す。

### 出題ソース

1. **静的な問題バンク**（学部横断の例文）— 初回はこれだけで回す
2. **本人の答案から**— 本添削の `languageCorrections`（`typo / grammar / connector / expression / redundancy`）が
   溜まったら、本人が実際に間違えた文を出題する。Phase 2 以降の「反復」枠はこれを使う

`quantitativeAnalysis` は既に一文の長さ・接続詞の種類数を数えているので、
「あなたの平均一文は78字（目安60字）」のような提示も追加実装なしで出せる。

## 6. カリキュラム（全20講）

進行の目安：1講あたりアニメ8〜12分＋ドリル3分＋課題10〜25分。

| Phase        | #   | 講                     | 学ぶこと                                               | 課題                                    | 埋め込みドリル               |
| ------------ | --- | ---------------------- | ------------------------------------------------------ | --------------------------------------- | ---------------------------- |
| 0 導入       | 1   | 小論文とは何か         | 作文との違い。採点5観点がそのままAIの採点軸であること  | 200字・自由に1本（現状把握）            | —                            |
| 1 型を組む   | 2   | 型の全体像             | 6ブロックの並びと役割。良い答案／悪い答案の対比        | 型のブロックに答案を分解する（選択）    | 文末・語彙                   |
|              | 3   | 立場を決める           | 一つに決める。問いに正対する。曖昧語を消す             | ②立場だけ 60字                          | 主述の一致                   |
|              | 4   | 理由を書く             | 主張の言い換えにしない。理由は1本に絞る                | ③理由だけ 100字                         | 一文を切る                   |
|              | 5   | 根拠・具体例           | 一般論ではなく事実・経験・数字。抽象語を落とす         | ④根拠だけ 150字                         | てにをは                     |
|              | 6   | 譲歩と反論             | 反対側の最も強い言い分を書く。切り返しで立場を強める   | ⑤譲歩＋反論 150字                       | 冗長                         |
|              | 7   | 結論                   | 新情報を足さない。立場を言い直す。字数の残し方         | ⑥結論だけ 80字                          | 係り受け・指示語             |
|              | 8   | ブロックをつなぐ       | 段落の切り方、接続表現、一段落一主張                   | ②〜⑥をつないで 400字                    | 反復（弱い種類）             |
| 2 中身の質   | 9   | 事実と意見を分ける     | 事実・推測・意見の区別。断定していい範囲               | 混在文を3分類して書き直す 200字         | 反復                         |
|              | 10  | 抽象語を具体に落とす   | 「社会問題」「多様性」を扱える大きさに切る             | 抽象語1つを具体化 200字                 | 反復                         |
|              | 11  | 自分の経験の使い方     | 独自性の正体。経験を主張の根拠に変換する               | 自分の経験を④として 200字               | 反復                         |
| 3 読む・分析 | 12  | 設問分析               | 問われていることに正対する。条件を全部拾う             | 設問から書くべき要素を列挙              | 反復                         |
|              | 13  | 課題文の読み方         | 筆者の主張と論拠をつかむ。要約と意見を分ける           | 課題文を150字で要約（要約ドリルへ誘導） | 反復                         |
|              | 14  | 資料・データの読み取り | グラフから言えること／言えないこと。相関と因果         | 読み取り＋解釈 200字                    | 反復                         |
| 4 型を変形   | 15  | テーマ型               | テーマから論点を立てる                                 | フル答案 600字                          | 反復                         |
|              | 16  | 課題文型               | 要約を①に収める。引用の使い方                          | フル答案 800字                          | 反復                         |
|              | 17  | 資料型                 | 7ブロックの型。因果の断定を避ける                      | フル答案 800字                          | 反復                         |
|              | 18  | 解決策提示型           | 原因→解決策→実現可能性。副作用に触れる                 | フル答案 800字                          | 反復                         |
| 5 仕上げ     | 19  | 推敲と減点潰し         | 原稿用紙ルール、誤字、表記ゆれ、見直しの順序           | 自分の過去答案を推敲して再提出          | 総合（本人の赤ペン履歴から） |
|              | 20  | 本番の時間配分         | 60分の使い方。構想20分・執筆30分・見直し10分。字数調整 | 時間制限つきフル答案 800字              | —                            |

## 7. アニメーションの型（4パターン）

シーンを毎回ゼロから作らず、4つの見せ方の組み合わせで全講をまかなう。

| パターン               | 見せ方                                                                          | 使う講         | 実装 |
| ---------------------- | ------------------------------------------------------------------------------- | -------------- | ---- |
| 原稿用紙タイプ         | 原稿用紙のマス目に1文ずつ書かれていき、書かれた文が型のどのブロックかを左に表示 | 2〜8講         | P1   |
| ブロック積み上げ       | 6ブロックのカードが順に積まれ、抜けたブロックがあると赤く欠ける                 | 2, 8, 15〜18講 | P1   |
| ビフォー／アフター対比 | 悪い文が左、直した文が右。差分の語だけ色が変わる                                | 9〜11, 19講    | P2   |
| 図解                   | グラフ・時間配分の円など、静止図に順に注釈が出る                                | 14, 20講       | P3   |

再生は自動と手動の両方（「進む／戻る」で自分のペース、スキップ可）。1シーン＝1メッセージ、
1講あたり6〜10シーン。

## 8. データ構造の拡張

既存 `src/data/essay-lectures/types.ts` を次のように広げる（既存フィールドは残す）。

```ts
/** 講義アニメの1シーン */
export interface LectureScene {
  id: string;
  /** 画面下に出る説明文（1シーン1メッセージ） */
  caption: string;
  /** 見せ方のパターン */
  visual: "manuscript" | "blocks" | "compare" | "diagram";
  /** visual ごとの中身（原稿用紙に書かれる文、対比の前後など） */
  payload: SceneManuscript | SceneBlocks | SceneCompare | SceneDiagram;
  /** ハイライトする型のブロック */
  highlightBlock?: EssayBlockId;
}

/** 型の6ブロック。講義・課題・添削で共通のID */
export type EssayBlockId =
  | "question"
  | "position"
  | "reason"
  | "evidence"
  | "concession"
  | "conclusion";

/** 埋め込みドリル */
export interface LectureDrill {
  kind:
    | "particle"
    | "subject_predicate"
    | "sentence_length"
    | "modifier"
    | "style"
    | "redundancy";
  /** 静的な問題。空なら本人の赤ペン履歴から生成 */
  items: DrillItem[];
}

export interface EssayLecture {
  // 既存: id, order, level, title, summary, durationMin, keyTakeaways
  scenes: LectureScene[]; // sections を置き換え（sections は移行完了まで残す）
  drill?: LectureDrill;
  exercise: LectureExercise & {
    /** 型のどのブロックを書かせるか。フル答案なら null */
    blockId: EssayBlockId | null;
    /** 設問タイプ（Phase 4 で使う） */
    questionType?: "theme" | "passage" | "data" | "solution";
  };
}
```

添削へは `focusPoints` に加えて `blockId` を渡し、フィードバックを型のブロック名で返す。
弱点DBへの登録も同じ語彙にする（既存の `weakness-category` の5軸と併記）。

進捗は既存 `/api/essay/lecture/history` を使い、ドリルの正答率を足す。

## 10. 未決事項

- 管理者側で「どの講で詰まっているか」を見る画面が要るか（生徒詳細タブへの追加）
